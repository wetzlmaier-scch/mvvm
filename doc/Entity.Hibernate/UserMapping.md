# `Entity.Hibernate/UserMapping.cs`

### Purpose

This file is the Fluent NHibernate mapping for the `User` entity. It exists to tell NHibernate how the `User` domain object (defined in `Entity.Hibernate/User.cs`) corresponds to a relational table in SQL Server, so that the ORM can read and write `User` records transparently.

### Role in the Codebase

It lives in the `Entity.Hibernate` project, which is a mapping-assemblies project: its only job is to pair entities with their Fluent NHibernate mappings. The `DataAccessLayer.Hibernate/SessionFactoryBuilder.cs` class builds the session factory by loading Fluent mappings from assemblies passed in as `mappingAssemblies` (via `FluentMappings.AddFromAssembly`), so this mapping is discovered by convention — it does not need to be referenced by name anywhere. It also runs `SchemaUpdate` against the configuration, so the `Users` table and its columns are created/updated automatically at startup based on the rules in this class. If this mapping were removed, `User` entities could no longer be persisted or loaded through NHibernate, and schema auto-update would no longer manage the `Users` table.

### Relationships

- **`ClassMap<User>`** (FluentNHibernate.Mapping, external library): the base class whose constructor body is the mapping itself. The `Map`, `Id`, and `Table` calls are Fluent NHibernate's fluent API.
- **`User`** (`Entity.Hibernate/User.cs`, same project): the entity being mapped. It derives from `Entity<int>` (`DataAccessLayer/Entity.cs`), which supplies the `Id` property that this mapping maps as the primary key.
- **`SessionFactoryBuilder`** (`DataAccessLayer.Hibernate/SessionFactoryBuilder.cs`): the consumer — it picks this mapping up by scanning the `Entity.Hibernate` assembly, and its `SchemaUpdate` call materializes the schema described here.

### Behavior & Details

The constructor defines the full shape of the `Users` table:

- `Table("Users")` — the entity maps to a table literally named `Users`, not the NHibernate default (which would also be "Users" for this type, so this is explicit rather than consequential).
- `Id(x => x.Id).GeneratedBy.Identity()` — `Id` (inherited from `Entity<int>`) is the primary key, generated by the database as an identity column. NHibernate will not accept a client-supplied id on insert; it reads the generated value back after the insert.
- `Map(x => x.FirstName).Not.Nullable().Length(50)` — `FirstName` is a required `nvarchar(50)` column.
- `Map(x => x.LastName).Not.Nullable().Length(50)` — `LastName` is a required `nvarchar(50)` column.
- `Map(x => x.IsActive).Not.Nullable()` — `IsActive` is a required bit column with no length restriction.

All columns are non-nullable, so NHibernate will reject or fail a save if any of these properties is unset. Note that `User`'s parameterless constructor (the one NHibernate uses for hydration) leaves `FirstName` and `LastName` as null and does not set `IsActive`, which is fine for loading but means the `Not.Nullable()` constraints only matter when the application sets values — the `User(string, string)` constructor does so, including `IsActive = true`.
