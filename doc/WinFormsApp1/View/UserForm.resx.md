# WinFormsApp1/View/UserForm.resx

### Purpose

This is the resource file (`*.resx`) for the `UserForm` window. It is the standard WinForms sidecar generated by the visual designer that stores designer metadata for the form's controls. In practice this instance is nearly empty: apart from the boilerplate ResX header and schema, it holds a single entry — `errorProvider.TrayLocation` (`17, 17`) — which records where the `ErrorProvider` component sits on the designer's component tray so the designer can redraw it consistently when the form is opened in design view.

### Role in the Codebase

`UserForm.resx` sits next to `UserForm.cs` and `UserForm.Designer.cs` in `WinFormsApp1/View/`. The trio is the standard WinForms split: the designer file builds the control tree, the `.cs` file holds hand-written logic, and the `.resx` is compiled into a resources satellite for the form. The `.csproj` (SDK-style, `UseWindowsForms` enabled) picks up the `.resx` automatically; no explicit item entry is needed.

Nothing at runtime depends on its content. The only entry, `errorProvider.TrayLocation`, is consumed by the WinForms designer, not by the running application. Removing the file would not break the build or the form's behavior; at worst the designer would lose the remembered tray position of the non-visual `ErrorProvider` component.

### Relationships

- Pairs with `UserForm.cs` (hand-written bindings to `IUserViewModel`) and `UserForm.Designer.cs`, which declares the `errorProvider` control this metadata describes.
- No code in the project reads `UserForm.resources` directly; it exists purely for the designer and the resource-compilation pass.

### Behavior & Details

The file contains the standard ResX schema, resheaders (`resmimetype`, `version`, reader/writer pointing at `System.Resources.ResXResourceReader`/`Writer`), and exactly one `<metadata>` element:

```xml
<metadata name="errorProvider.TrayLocation" type="System.Drawing.Point, ...">
  <value>17, 17</value>
</metadata>
```

There are no `<data>` entries — the form holds no localized strings or embedded images. Any change to designer-only component layout in the designer regenerates this file automatically; it should not be edited by hand.
