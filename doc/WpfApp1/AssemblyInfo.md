### Purpose

`WpfApp1/AssemblyInfo.cs` sets one assembly-level attribute, `[assembly: ThemeInfo]`, on the WpfApp1 WPF application. It tells WPF's resource system where to find theme resources when a resource lookup fails at the page or application level.

This file exists because WPF uses `ThemeInfo` to resolve theme-dependent resources (brushes, styles, etc.) from theme dictionaries at runtime. Without it, the default behavior differs from the one declared here.

### Role in the Codebase

This is standard scaffolding generated by Visual Studio for any WPF project; it lives alongside `App.xaml` / `App.xaml.cs`, which are the actual application entry point of WpfApp1. Nothing in the project references the `ThemeInfo` attribute directly — WPF's resource loader consumes it implicitly. Removing the file would not break the build, but WPF would fall back to its default resource-location assumptions. In practice, since this project does not ship theme dictionaries, removing it changes nothing observable.

### Relationships

The file depends only on `System.Windows` (the `ThemeInfoAttribute` and `ResourceDictionaryLocation` enum from the WPF framework, both external to this repository). No other project file imports or depends on this file.

### Behavior & Details

The attribute is applied with two arguments:

- `ResourceDictionaryLocation.None` — theme-specific resource dictionaries are not expected anywhere, so WPF skips that step of the lookup chain.
- `ResourceDictionaryLocation.SourceAssembly` — the generic (non-theme) resource dictionary is the compiled source assembly itself, i.e. `WpfApp1.dll`'s `themes/Generic.xaml` convention.

So at runtime, if a resource cannot be found in a page or the application resource dictionaries, WPF looks for it in the source assembly's generic resource dictionary and stops there. There is no other logic in this file; it contains no classes, methods, or state.
