### Purpose

`IShowUsersViewModel` is the contract for the view model that displays the list of active users in the UserManagement module. It exists so that the parent view model (`IUserViewModel`) can hold a reference to the "show users" pane through an abstraction rather than the concrete `ShowUsersViewModel` class — the concrete class is resolved at runtime via MEF composition.

### Role in the Codebase

This file is part of the `UserManagement/ViewModel` folder, where each view model follows the pair pattern: an interface in its own file, and a concrete class that implements it and is exported with `[Export(typeof(...))]`. `IUserViewModel` declares a `ShowUsersViewModel` property of this interface type, so the main user-management view model composes the sub-views by their interfaces and MEF hands back the concrete implementations. If this interface were removed, `IUserViewModel` and `UserViewModel` would lose the type they use to hold the show-users pane.

### Relationships

- **Implemented by** `ShowUsersViewModel` (same folder), which additionally inherits from `ViewModelBase` and is tagged `[Export(typeof(IShowUsersViewModel))]`, so it is this interface's only implementation in the codebase.
- **Consumed by** `IUserViewModel` and `UserViewModel` in the same folder, which expose a `ShowUsersViewModel` property typed as `IShowUsersViewModel`.
- **Depends on** types from other layers it re-exposes:
  - `UserModel` (`UserManagement/Model`) — the display model for a single user, with observable `FirstName`/`LastName` properties.
  - `IUserService` (`BusinessLayer`) — the service that fetches and manages users; the implementation marks its `UserService` property with `[Import]`.
  - `ILoggingService` (`Logging`) — logging, likewise injected via `[Import]` in the implementation.
  - `IAsyncRelayCommand` (CommunityToolkit.Mvvm) — the standard MVVM command type for async handlers.

### Behavior & Details

The interface has no logic; its shape defines what a consumer may rely on:

- `Users` — a read-only `ObservableCollection<UserModel>` bound to the user list in the UI. The implementation populates it when the view loads and appends to it when a `UserChangedMessage` of type `Added` arrives via the `WeakReferenceMessenger`.
- `UserService` and `LoggingService` — get/set properties whose setters exist only because MEF injects the imports into the implementation; consumers should treat them as read-only dependencies.
- `LoadedCommand` — an `IAsyncRelayCommand` generated by the `[RelayCommand]` attribute on the implementation's `OnLoadedAsync`. A view binds to it (typically on a `Loaded` event) to trigger the initial fetch.
- `OnLoadedAsync` — the public async method behind that command. In the implementation it awaits `UserService.GetActiveUsers()` and adds each result to `Users` as a new `UserModel` with `FirstName` and `LastName` copied from the returned `UserDto`. Note that the interface exposes the raw method in addition to the generated command, so callers can invoke it directly without going through the command.

Rough edges: the implementation only handles the `Added` case of `UserChangedMessage`; `Updated` and `Deleted` both throw `NotImplementedException`, so the `Users` collection will grow stale in those scenarios until implemented.
